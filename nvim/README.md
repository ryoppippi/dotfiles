# Neovim Configuration

## Structure

- `init.lua` - Entry point
- `lua/` - Lua configuration modules
- `nvimx-lock/` - Plugin lock generated by nvimx (`plugins.json`, `flake.nix`, `flake.lock`)

## Plugin Manager

**Lazy.nvim** loads plugins; [**nvimx**](https://github.com/myuron/nvimx)
supplies every non-dev one read-only from the Nix store
(`nix/modules/home/programs/neovim/`):

- `nvimx-lock` (or `nix run .#nvim-lock` before the first switch) evaluates
  the lazy.nvim spec headlessly and pins each plugin in `nvimx-lock/flake.lock`.
  Spec `version`/`branch`/`commit` pins are honoured at lock time.
  The pre-commit hook re-locks automatically when `lua/plugin/` changes;
  existing pins never move.
- `nix run .#nvim-lock -- --update [name...]` moves pins forward. Commit the
  lock and switch to apply.
- lazy.nvim never clones, installs or updates anything at runtime: nvimx's
  wrapper forces its `dev` path at the Nix farm and disables the installer.
  `build` steps that are Neovim commands (e.g. `:KanagawaCompile`) are skipped;
  `nvimx-lock` lists them.
- Own plugins marked `dev = true` load from `~/ghq/github.com/ryoppippi/<name>`.

See `nix/modules/home/programs/neovim/ROADMAP.md` for the design history.
